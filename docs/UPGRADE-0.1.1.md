# 0.1.1：修复资源管理器拒绝访问

## 已有证据与本次修改

用户 VM 中的 0.1.0 验证脚本已返回 NTFS、exFAT 全部 PASS。这证明该次运行中的
创建、格式化、管理员读写和重挂载成功。资源管理器的“拒绝访问”需要单独检查
普通权限访问，不能仅根据无容量显示就断定未格式化。

旧版磁盘设备 ACL 仅允许 SYSTEM/管理员，且设置 FILE_DEVICE_SECURE_OPEN。
普通资源管理器通常没有启用的管理员 SID，因此无法正常访问。旧验证脚本全程
以管理员运行，遗漏了这个权限场景。旧版 GUI 还会把瞬时连接失败消息留在连接
已经恢复的界面，导致出现“连接错误码 0”与历史错误消息并存。

本次修改：

- 磁盘命名空间允许已认证用户访问；新 NTFS 卷根目录授予已认证用户可继承的修改权限。
- 内核控制设备、管理管道保持管理员/SYSTEM 限制；对原始数据打开单独校验请求中
  捕获的令牌，不能仅凭用户属于管理员组就放行被过滤的管理员令牌。
- 修复管道重建期间的瞬时连接竞态，分开显示当前连接状态与最近操作结果。
- 将日常“不支持某可选控制码”的特性探测与数据读写失败计数分开。
- 标题栏按钮改用程序绘制线条，不再依赖字体中缺失的符号。
- 验证脚本加入受限令牌测试；新增 memdisk-access-test.exe，可在普通终端手工验证。

## 更新方法（全部在 VM 中执行）

1. 关闭旧 GUI，以及占用内存盘文件的程序。保存需要保留的文件到其他盘。
2. 在旧目录的管理员 PowerShell 中列出实例，逐个显式销毁。销毁会丢弃其全部文件。

```powershell
.\memdisk.exe driver-list
# 将下面的 3 替换为上一步实际返回的实例 ID。
.\memdisk.exe destroy 3 --yes
.\Uninstall.ps1
```

若销毁提示文件占用，关闭相关窗口/句柄后重试，不进行强制卸载。不要仅覆盖旧
运行中的 SYS/EXE；旧驱动必须先成功卸载。旧 CLI 偶发连接失败可重试，或使用新版
CLI 连接同一 v1 管理协议。

3. 将 MemDisk-0.1.1-dev-win-x64.zip 解压至新的固定目录，进入该目录的管理员终端：

```powershell
.\Install.ps1
.\Verify.ps1
.\memdisk-ui.exe
```

原有 VM 测试签名设置继续使用，不需要重新安装任何开发工具。本次沿用本机构建
证书；安装脚本会导入随包公开证书。

4. 创建 NTFS 或 exFAT 磁盘后，用普通资源管理器查看容量并创建、修改、删除文件。
再打开非管理员 PowerShell，在新版目录运行（R 替换为实际盘符）：

```powershell
.\memdisk-access-test.exe R
```

预期：容量和普通文件读写通过，原始数据访问与管理接口被拒绝。测试只针对
QueryDosDevice 确认的 MemDisk 设备，临时文件自动删除，不向原始磁盘写入数据。

## 若仍失败

保留 Verify.ps1 中受限令牌测试的完整错误，以及普通终端访问测试结果。新版本
不能在旧驱动未卸载的情况下正确验证权限变更。

磁盘管理中没有新磁盘是当前 legacy、非 PnP 设备实现的已有范围限制，与本次
资源管理器拒绝访问是两件事；本次未将驱动切换为 PnP/Storport 实现。

参考：[Windows 驱动设备命名空间访问检查](https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/controlling-device-namespace-access)。
