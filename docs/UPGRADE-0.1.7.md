# 0.1.7：基准测试句柄生命周期

修复此前基准测试持有多余卷句柄、提前显示结束，以及测试与磁盘管理操作
没有按实例互斥的问题。固定顺序负载、数据校验与 v1 协议不变。

- 实例身份校验结束后立即关闭仅用于校验的卷句柄。
- 测试函数返回并关闭文件、事件和缓冲区后，才显示完成、取消或失败。
- 停止会取消待处理的文件 I/O，并等待请求完成后清理；此期间保持运行状态。
  底层驱动不响应取消时仍须等待，不能释放仍被请求使用的资源。
- 同一 GUI 内，测试开始与管理请求共用准入锁；测试及清理期间按实例 ID
  阻止挂载、卸载和销毁。切换页面、选择其他实例不会解除目标实例的保护。
- GUI 退出时停止并等待测试线程清理。

## 更新

此修复只改变用户态 GUI，0.1.6 的服务和驱动可以保留。
停止旧 GUI 的测试，退出旧 GUI，将 0.1.7 包解压至新目录，运行其中
memdisk-ui.exe；无需覆盖运行中的驱动或销毁已有磁盘。
如果从 0.1.5 或更早版本升级且需要新容量策略，另按 CAPACITY-UPDATE.md
同步替换组件。已经发生的 NTFS 锁卷失败不保证仅更新 GUI 就能恢复。

## 隔离 VM 回归

1. 分别用 NTFS/exFAT 创建测试盘，运行基准测试并核对数据校验成功。
2. 在测试及停止清理期间切换到磁盘管理；该实例的管理按钮应禁用。
   其他实例仍可管理；确认框也必须核对其绑定的实例。
3. 测试完成后立即卸载、重挂载、销毁；失败保留实例和完整错误。
4. 重复启动、停止；停止显示结束后确认临时文件已消失，再安全卸载。
   固定负载可能很快完成，取消与自然完成竞争应同样安全。
5. 测试中关闭 GUI，确认进程退出后不再保留测试卷/文件句柄。
6. 从第二个客户端同时请求卸载时，依旧要求锁卷成功；不能因本地保护而
   绕过安全卸载。系统或外部访问造成锁卷失败时保留实例。

主机回归使用可控工作任务验证正常、失败、异常、取消路径的清理时序，
并通过命名管道验证真实待处理异步读的取消及再次使用；不加载驱动或格式化卷。
这些检查不能替代 VM 的文件系统和驱动运行证据。
