# 0.1.8：重启及部分卸载后的清理

驱动和管理服务均按需启动。重启后驱动可能未加载，此时 driver-list 不能
打开控制设备。旧脚本无条件要求查询成功，因而即便没有磁盘也拒绝卸载。
直接 sc.exe delete 仅删除或标记删除服务注册项，不等于卸载运行中的驱动。

新版卸载同时核对 SCM 驱动状态及控制设备：

- 驱动运行且枚举成功、无磁盘：先移除管理服务，重新检查，再停止并移除驱动。
- 控制设备返回文件不存在（错误 2），SCM 同时确认驱动停止或不存在：允许清理。
- 已不存在的注册项可重复清理；停止操作会等待完成并释放 SCM 查询句柄。
- 有磁盘、协议异常、访问被拒绝、运行中但控制设备不可访问：停止并报告具体状态。
- 注册项不存在但控制设备仍在：视为不一致，停止清理，重启后再核对。
- 删除仍待完成时说明关闭服务管理工具、重启并重试，不谎报成功。

CLI JSON 用 UTF-16 转义保持 ASCII 输出，避免中文错误在原生程序与
PowerShell 代码页不一致时截断。协议字段和错误码含义不变。

## 使用

将 0.1.8 包解压到新目录，在该目录的管理员 Windows PowerShell 5.1 中运行：

```powershell
.\Check-Package.ps1
.\Uninstall.ps1
```

可以用新目录中的脚本清理旧注册项；无需先安装或启动新版驱动。
Uninstall.ps1、Uninstall-Helpers.ps1 和 memdisk.exe 必须来自同一个新包。
保留证书和启动安全设置，按 README-VM.md 单独处理这些设置。

## 隔离 VM 验证

1. 创建磁盘后卸载：必须拒绝，实例保留；显式安全销毁后方可卸载。
2. 无实例且驱动运行：服务和驱动均停止并删除注册项。
3. 安装后重启，不创建实例：直接卸载应成功，不会为查询而启动驱动。
4. 在快照 VM 中重启后删除驱动注册项，保留已停止的管理服务：新版能清理剩余项。
5. 两项均不存在时再次卸载应成功；对访问拒绝、异常响应和停止失败保持失败关闭。
6. 若 sc.exe 报待删除或检测到注册/设备状态不一致，关闭管理工具并重启后复查。

构建机仅做状态机模拟、PowerShell 5.1/7 解析检查和用户态测试，不执行卸载。
